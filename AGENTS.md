# AGENTS.md

Инструкции для любого AI-агента, работающего в этом проекте
(Claude Code, Codex, Cursor, Copilot и др.).

## О проекте
- Что это: интерактивный симулятор парадокса Монти Холла — можно сыграть вручную
  и прогнать авто-симуляцию на 100/1000 раундов, чтобы увидеть, что смена двери
  выигрывает ~2/3 против ~1/3. Для всех, кто объясняет или изучает вероятности.
- Стек: TypeScript 5.8, React 19, Vite 6, Tailwind CSS 3 (локальная сборка через
  PostCSS + autoprefixer, плагин tailwindcss-animate), recharts 3 для графиков,
  vite-plugin-singlefile для офлайн-сборки. Пакетный менеджер — npm.
  Бэкенда и БД нет: всё считается в браузере, состояние — в localStorage.
  Аналитика — Яндекс Метрика, подключается только после согласия пользователя.
- Запуск: `npm install && npm run dev` → http://localhost:3000
- Сборка: `npm run build` (сайт в `dist/`), `npm run build:offline`
  (один автономный HTML-файл в `dist-offline/`)
- Тесты: автотестов нет. Проверка — `npm run typecheck` (tsc в strict-режиме)
  плюс ручной прогон в браузере: раунд целиком, симуляция, темы, RU/EN,
  клавиатура, ширины 320/390/1440.
- Линтер/форматтер: не настроены. Стиль поддерживается вручную по rules/20-code-style.md.

## Правила
Перед работой прочитай и соблюдай ВСЕ файлы в папке `rules/`:

- [rules/00-process.md](rules/00-process.md) — порядок работы: понять → спланировать → сделать → проверить → отчитаться
- [rules/10-architecture.md](rules/10-architecture.md) — архитектура, структура, зависимости, ошибки
- [rules/20-code-style.md](rules/20-code-style.md) — именование, комментарии, функции, форматирование
- [rules/30-git.md](rules/30-git.md) — коммиты, ветки, что запрещено коммитить
- [rules/40-testing.md](rules/40-testing.md) — тесты и обязательная проверка результата
- [rules/50-security.md](rules/50-security.md) — секреты, валидация ввода, доступ
- [rules/60-ui-ux.md](rules/60-ui-ux.md) — состояния экранов, формы, доступность
- [rules/70-docs.md](rules/70-docs.md) — README, актуальность, фиксация решений

## Главные принципы (короткая версия)
1. Сначала пойми задачу и существующий код, потом пиши. Не гадай — проверяй.
2. Простое решение лучше умного. Не добавляй абстракций и настроек «на будущее».
3. Каждое изменение — проверено: код запущен, тесты пройдены, результат виден.
4. Маленькие шаги: одна задача — одно изменение — один коммит.
5. Отвечай лаконично и по делу: сначала результат, потом детали. Без воды.
6. Секреты никогда не попадают в код и в git.
7. Не трогай код вне задачи: без попутных переименований и «улучшений».
