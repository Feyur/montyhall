# Git

## Базовое
- Инициализируй git с первого дня проекта, даже для «наброска».
- `.gitignore` — до первого коммита: зависимости, сборка, `.env`, файлы IDE, OS-мусор.
- Lock-файл зависимостей — всегда в git.

## Коммиты
- Один коммит — одно логическое изменение. «Починил баг + переименовал файлы
  + добавил фичу» — это три коммита.
- Сообщение отвечает «что и зачем», в повелительном наклонении:
  `Add order export to CSV`, `Fix crash on empty cart`.
  Плохо: `fix`, `wip`, `изменения`, `финальная версия 2`.
- Формат: короткая тема ≤ 72 символов; если нужны детали — пустая строка и абзац.
- Коммить только рабочее состояние: код собирается, тесты проходят.
- Перед коммитом просмотри diff целиком: случайные файлы, отладочные
  `print`/`console.log`, закомментированный код — вычистить.

## Ветки
- `main` всегда в рабочем состоянии — из него можно деплоить в любой момент.
- Фичи и фиксы — в отдельных ветках: `feature/csv-export`, `fix/empty-cart-crash`.
- Ветка живёт коротко: слил — удалил. Долгоживущие ветки = болезненные конфликты.

## Запрещено
- Коммитить секреты (ключи, пароли, токены) — даже «на минутку».
  Попал секрет в историю — считай его скомпрометированным и меняй.
- `git push --force` в общие ветки.
- Переписывать историю уже запушенных общих веток.
- Коммитить сгенерированные артефакты (сборка, кэши) — им место в `.gitignore`.
