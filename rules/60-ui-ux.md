# UI / UX

(Для проектов с интерфейсом: сайт, веб-приложение, мобильное, десктоп.
Для CLI/API — можно удалить.)

## Консистентность
- Дизайн-токены в одном месте: цвета, отступы, шрифты, радиусы — переменные,
  а не «магические» значения по компонентам.
- Одинаковые вещи выглядят и ведут себя одинаково во всём приложении:
  одна кнопка «основного действия», один стиль форм, один тон сообщений.
- Сетка отступов — кратная (4px или 8px), без «на глаз».

## Каждый экран имеет все состояния
Экран без этих состояний — недоделан:
1. **Загрузка** — скелетон или спиннер, интерфейс не «прыгает».
2. **Пусто** — не белый экран, а объяснение и действие («Пока нет заказов. Создать?»).
3. **Ошибка** — что случилось и что делать, по-человечески. Не `Error 500`.
4. **Данные** — нормальный случай, включая ОЧЕНЬ длинные тексты и большие списки.

## Формы
- Валидация — сразу у поля, а не общим алертом после отправки.
- Сообщение об ошибке говорит, как исправить: не «Неверный ввод»,
  а «Пароль должен быть не короче 8 символов».
- Кнопка отправки блокируется на время запроса — двойные отправки недопустимы.
- Введённое пользователем не теряется при ошибке.

## Доступность (минимум, не опция)
- Весь интерфейс проходится с клавиатуры; виден фокус.
- Контраст текста достаточный (WCAG AA, 4.5:1 для обычного текста).
- У картинок — alt, у иконок-кнопок — подпись (aria-label).
- Семантичный HTML: кнопка — `<button>`, ссылка — `<a>`, заголовки по порядку.
- Смысл не передаётся ТОЛЬКО цветом.

## Отзывчивость
- Любое действие пользователя получает мгновенный отклик (< 100 мс):
  нажал — увидел реакцию, даже если операция долгая.
- Мобильные экраны — не «потом»: проверяй вёрстку на узком экране сразу.
- Деструктивные действия (удалить, отменить заказ) — с подтверждением
  или возможностью отмены.

## Текст в интерфейсе
- Коротко, по-человечески, без жаргона разработчика.
- Один язык и один тон во всём приложении.
- Заглушки «Lorem ipsum» и «TODO» не доезжают до пользователя.
