# Безопасность

## Секреты
- Ключи, пароли, токены — только в переменных окружения / секрет-хранилище.
  Никогда: в коде, в git, в логах, в сообщениях об ошибках, во фронтенд-бандле.
- В репозитории лежит `.env.example` с именами переменных без значений;
  сам `.env` — в `.gitignore`.
- Секрет попал в git — он скомпрометирован: сменить ключ, не просто удалить файл.

## Ввод — всегда враждебный
- Валидируй ВСЁ, что приходит снаружи: формы, параметры URL, заголовки,
  файлы, ответы сторонних API.
- Валидация на клиенте — для удобства; на сервере — обязательна.
- SQL — только параметризованные запросы. Никакой конкатенации строк в запрос.
- Вывод пользовательских данных в HTML — только с экранированием (защита от XSS).
- Загрузка файлов: проверяй тип, размер, имя; храни вне корня приложения.

## Доступ
- Проверка прав — на сервере, на каждом эндпоинте. Спрятанная кнопка — не защита.
- Принцип минимума: у пользователя, токена, сервиса — только те права,
  что нужны для их задачи.
- Не выдавай наружу внутренности: stack trace, версии, пути к файлам —
  только в серверные логи, пользователю — общее сообщение.
- Пароли — только через проверенный алгоритм хэширования (bcrypt/argon2),
  никогда своя криптография.

## Зависимости
- Периодически прогоняй аудит (`npm audit`, `pip-audit` и т.п.), критичное — обновляй.
- Не ставь пакеты «наугад» из непроверенных источников; опечатки в именах
  пакетов — реальный вектор атаки.

## Здравый смысл
- Всё, что ходит по сети, — по HTTPS.
- Логируй действия, но не логируй персональные данные и секреты.
- Если делаешь что-то, связанное с деньгами, персональными данными или
  авторизацией, — перепроверь дважды и покрой тестами.
